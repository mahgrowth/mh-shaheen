# LEG-06 · سجل المخاطر القانونية

تطلع المخاطر القانونية من ملفات شركتك نفسها (العقود، الشركاء، البيانات، الموظفين، المحتوى)، تعطي كل خطر درجة = الاحتمال × الأثر على مصفوفة 5×5، وتحدد لكل واحد مالك ومعالجة وموعد مراجعة، ومتى لازم مختص

## متى تشتغل

**تشتغل لما:**
- المستخدم يقول: شنو المخاطر القانونية علي؟ سجل المخاطر، فحص قانوني
- مراجعة دورية: الموعد بـ`calendar.md` (افتراضياً كل 3 شهور [تخمين])
- CEO-13 (فحص صحة الشركة) يطلب البعد القانوني، والإدارة مفعّلة
- قبل قرار كبير يسجّله CEO-05: توظيف أول موظف، دخول دولة ثانية، منتج جديد، شريك جديد، عقد كبير
- LEG-03 أو LEG-10 أو LEG-09 طلّعوا خطر لازم ينضاف

**ما تشتغل لما:**
- عقد معيّن تبي تراجعه ← LEG-03
- خلاف صاير فعلاً ← LEG-09
- تسرب بيانات صاير الحين ← LEG-10
- مخاطر مالية أو تشغيلية بس ← FIN أو OPS (السجل هني قانوني، ويقدر يشير لهم)

**شرط الإدارة (سطر ثابت):**
اقرا `COMPANY.md` و`org.json` أول شي · لو إدارة `leg` حالتها «خامل» أو «موقوف»: لا تشتغل، ورجّع للـCEO الطلب وليش يحتاج هالإدارة (CEO-02)

## الأسئلة

**قواعد السؤال:** سؤال واحد بكل رسالة · أغلب الشغل من الملفات، فالأسئلة قليلة

1. «فيه شي قانوني مضايقك الحين أو خايف منه؟» · (ليش: نبدأ باللي يقلقك، حتى لو مو بالملفات) · تقدر تتخطاه
2. «فيه عقود أو اتفاقات شفهية مع عملاء أو موردين أو شركاء ما انكتبت؟» · (ليش: الاتفاق الشفهي من أكثر المخاطر اللي ما تنشاف) · تقدر تتخطاه
3. «تبي تحدد مبلغ، أي التزام فوقه يحتاج مختص قبل ما توقع؟ (بعملة دولتك)» · (ليش: يصير قاعدة لكل الإدارة بعدين) · تقدر تتخطاه · الجواب يتسجل قرار عن طريق CEO-05

## الخطوات

1. **اجمع المصادر:** اقرا الملفات بالجدول فوق، واكتب قائمة بالمصادر اللي قريتها (بالاسم) واللي ما لقيتها
2. **طلّع المخاطر** بالفئات التسع، وسجّل لكل خطر مصدره (اسم الملف والقسم، أو «من كلامك»):

   | الفئة | أمثلة تدور عليها |
   |---|---|
   | الشكل والترخيص | ترخيص ينتهي · نشاط فعلي برا النشاط المرخص · قطاع منظم بدون موافقة |
   | العقود | شغل بدون عقد · عقود فيها بنود حمراء من LEG-03 · تجديد تلقائي قريب |
   | الشركاء | ما فيه اتفاق شركاء · حصص بأسماء غير الشركاء الفعليين · خلاف بادئ |
   | العملاء والمستهلك | سياسة استرجاع ناقصة أو تناقض الواقع · وعود بالتسويق ما تتحقق |
   | البيانات والخصوصية | ما فيه سياسة · السياسة ما تطابق خريطة البيانات · بيانات حساسة · أدوات مجهولة |
   | الملكية الفكرية | الاسم مو مسجل · شغل مصمم أو مستقل بدون تنازل مكتوب · صور أو خطوط بدون ترخيص |
   | العمالة | موظف أو مستقل بدون عقد · مستقل يشتغل مثل الموظف · تأمينات ناقصة (من HR-05) |
   | المحتوى والإعلان | ادعاءات بالإعلانات · مؤثرين بدون اتفاق · متطلبات إعلان بدولتك (من سجلها) |
   | النزاعات | مطالبة أو تهديد مفتوح · ديون على عملاء · شكوى رسمية |

   - الضرائب والزكاة مو هني ← FIN-10 · تقدر تشير لها بسطر
3. **قيّم كل خطر:**

   | الدرجة | الاحتمال (خلال 12 شهر) | الأثر |
   |---|---|---|
   | 1 | نادر | بسيط: إزعاج، بدون فلوس أو بمبلغ صغير جداً |
   | 2 | ممكن بس مستبعد | محدود: مبلغ ينتحمل أو تعطيل أيام |
   | 3 | ممكن | متوسط: مبلغ يأثر على شهر شغل، أو خسارة عميل مهم |
   | 4 | مرجح | كبير: مبلغ يأثر على أشهر، أو إيقاف نشاط مؤقت |
   | 5 | شبه متوقع | حرج: يهدد استمرار الشركة، أو مسؤولية شخصية عليك |

   - **الدرجة = الاحتمال × الأثر** · اكتب المعادلة لكل خطر، مثال «4 × 3 = 12» (أرقام المثال خيالية)
   - لو الكاش موجود بـ`COMPANY.md`: الأثر بالفلوس يتقاس بأشهر المصاريف = المبلغ المتوقع ÷ المصاريف الشهرية، والنتيجة تختار درجة الأثر · المعادلة تنكتب
   - **التصنيف:** 1–4 منخفض · 5–9 متوسط · 10–16 عالي · 20–25 حرج [تخمين لحدود الفئات، قابلة للتعديل]
   - التقييم تقدير مو حقيقة · كل درجة معاها سطر «ليش» · عند الشك بين درجتين: الأعلى
4. **متى مختص:** أي خطر «عالي» أو «حرج» · أو أي خطر من قائمة «لازم مختص» بـSKILL.md · ينكتب بعمود «مختص؟» «نعم، قبل <التاريخ أو الحدث>»
5. **المعالجة:** لكل خطر واحد من أربعة: تجنّب (توقف النشاط أو البند) · تقليل (عقد، سياسة، تعديل) · نقل (تأمين أو بند بالعقد) · قبول (بقرار مكتوب) · ومعاها الإجراء والمهارة اللي تسويه (مثل «مسودة اتفاق شركاء ← LEG-01»)
   - «قبول» خطر عالي أو حرج = قرار يتسجل عن طريق CEO-05
6. **المالك والموعد:** المالك صاحب الشركة دايماً (أو شخص يسميه هو) · الموعد تاريخ أو حدث
7. **قارن مع السجل القديم** لو موجود: خطر انضاف · خطر انشال وليش · درجة تغيرت (كان ← صار وليش)
8. **مرّر على LEG-08**
9. **احفظ وسجّل:**
   - `outputs/YYYY-MM-DD-leg-06-risk-register.md` · النسخة القديمة تبقى
   - `tasks.md`: مهمة لكل معالجة «عالي» أو «حرج» باسم المهارة المقترحة
   - `calendar.md`: موعد المراجعة القادمة
   - اقترح على CEO-06 يعرض بالداشبورد عدد المخاطر بكل تصنيف
10. **اختم** بـ«الخطوة القادمة» بسطر: أعلى خطر وأول إجراء له
